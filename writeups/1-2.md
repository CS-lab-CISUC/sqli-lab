# Level 1-2: WHERE Clause Bypass

**URL:** `/dashboard`

**Objective:** Retrieve confidential stadium entries that the application intentionally hides.

## Vulnerable Code

```python
query = f"SELECT id, nome, secao, data, confidencial FROM entradas WHERE nome LIKE '%{search}%' AND confidencial = 0"
cur.execute(query)
```

The `search` parameter is interpolated directly into the query. The `AND confidencial = 0` condition at the end is meant to hide restricted rows, but an attacker can inject a payload that comments out the rest of the WHERE clause before that condition is ever evaluated.

**Payload — comment out the confidential filter:**
```
search: ' OR 1=1--
```

The resulting query becomes:
```sql
SELECT id, nome, secao, data, confidencial FROM entradas WHERE nome LIKE '%' OR 1=1-- AND confidencial = 0
```

`OR 1=1` is always true, so every row matches. The `-- AND confidencial = 0` is commented out and never evaluated. All entries are returned, including those with `confidencial = 1`.

## Fixed Code

```python
query = "SELECT id, nome, secao, data, confidencial FROM entradas WHERE nome LIKE %s AND confidencial = 0"
cur.execute(query, (f"%{search}%",))
```

The search term is passed as a bind parameter. The driver escapes it as a literal string value, so any injected SQL syntax (quotes, `OR`, `--`) is treated as part of the search string rather than query logic.
